# Application stack integration

## Runtime composition

`main.tsx` validates the root element, awaits `prepareApplication`, then mounts
StrictMode → AppProviders → RouterProvider. Initialization failures show a reload
message and are reported to the console. AppProviders composes I18nextProvider,
QueryClientProvider, and AppearanceProvider.

| Source | Integration |
| --- | --- |
| [prepare.ts](../../src/app/prepare.ts) | Await bundled translations; optionally await the development worker |
| [providers.tsx](../../src/app/providers.tsx) | Shared providers and language/direction subscription cleanup |
| [query-client.ts](../../src/app/query-client.ts) | Stable QueryClient: 30-second freshness, one query retry |
| [appearance-store.ts](../../src/features/appearance/model/appearance-store.ts) | Per-provider Zustand store for appearance values |
| [appearance-provider.tsx](../../src/features/appearance/components/appearance-provider.tsx) | React context facade, persistence, device/storage subscriptions, and DOM theme sync |
| [http.ts](../../src/shared/api/http.ts) | Ky v2 defaults: `/api/`, ten-second timeout, no transport retries |
| [i18n.ts](../../src/shared/i18n/i18n.ts) | Stable i18next instance, bundled English/Chinese Home namespace, English fallback |
| [browser.ts](../../src/app/mocks/browser.ts) | MSW browser adapter with no default handlers |

Local drawer/group state stays in React. Zustand does not duplicate query cache or
language selection. Query/Ky are foundations for future API features; no backend
or production endpoint is added. The API base is independent of the SPA asset base.

## Home

Home retains the compact Layered stack layout, with six layers: Application,
Interface, State & data, Build, Workspace, and Testing. The added state/data row
shows React State, Zustand, TanStack Query, Ky, i18next, and react-i18next. Workspace
includes Husky/lint-staged; Testing includes MSW. A native English/Chinese selector
changes Home's text without remounting its route or resetting appearance.

Home is translated; existing English chrome, About, dialogs, and the not-found
view retain explicit English language tags. Language choice is session-only.

## Development mocking

Copy [.env.example](../../.env.example) to an ignored local environment file and
set `VITE_API_MOCKING=true` when interception is wanted. Restart Vite after changing
its environment. Startup only imports/starts MSW when both the development flag
and explicit opt-in are true. It awaits registration before rendering.

The worker URL is `${import.meta.env.BASE_URL}mockServiceWorker.js`, preserving
`/lab/react/v2/`. [public/mockServiceWorker.js](../../public/mockServiceWorker.js)
is generated by `pnpm exec msw init public --save` and excluded from Biome. Do not
edit it manually. Feature handlers can be composed when a real API contract exists.
The production development guard removes the browser adapter from JS bundles.

## Jest integration

Jest still uses Babel only for test transformation. Its ESM allowlist includes
MSW, Ky, and the runtime dependencies they load; `.mjs` is transformed as well.
The test plugin replaces supported Vite environment properties and resolves
`import.meta.url` to the source file URL, allowing MSW's WASM loader to find its
binary. V8 coverage preserves the serialized appearance bootstrap functions.

The [HTTP suite](../../src/shared/api/__tests__/http.test.ts) runs actual Ky
requests through MSW's Node interceptor and verifies Query caching/invalidation,
HTTP failure propagation, and cancellation. It uses an absolute test API base;
no external request is sent. The browser preparation suite tests the worker
adapter boundary. Real-browser registration and visual checks remain separate.

## Hooks and packaging

[prepare.js](../../scripts/prepare.js) skips CI, production, `HUSKY=0`, and missing
Git metadata before importing Husky. Once in a Git checkout, `pnpm prepare`
installs the hooks. [.husky/pre-commit](../../.husky/pre-commit) runs lint-staged,
whose [configuration](../../lint-staged.config.js) invokes safe Biome fixes only
for supported staged file types. Hooks are configured but cannot activate in this
workspace until it is a Git checkout. Full test/build checks remain separate. Hook activation and staged safe formatting
(including a path with spaces) were verified in a temporary Git checkout without
initializing this workspace.

Vite uses Rolldown's `codeSplitting.groups` to put React, React DOM, and scheduler
into a reusable `react-vendor` chunk. The Oxc/Rolldown pipeline, deployment base,
and source maps are preserved.

## Verification

Run `pnpm check`, `pnpm test:coverage`, and `pnpm build`. The global 90% threshold
for all four coverage metrics is unchanged. Browser verification remains necessary
for layout, keyboard controls, language selection, and real worker registration.
